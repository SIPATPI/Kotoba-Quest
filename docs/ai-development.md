# การใช้ AI ระหว่างพัฒนา Kotoba Quest

โปรเจกต์นี้เป็นสิ่งที่ผมคิดและค่อย ๆ พัฒนาขึ้นเอง โดยใช้ AI เป็นเครื่องมือช่วย เพราะตอนเริ่มทดลองทำเว็บผมยังไม่ได้มีพื้นฐานการเขียนโค้ดมากนัก

## ผมใช้ AI อย่างไร

ผมเริ่มจากกำหนดว่าอยากให้เกมทำอะไร วาดภาพรวมของหน้าจอและระบบ จากนั้นใช้ AI ช่วยออกแบบหรือเขียนโค้ดตามโจทย์ที่วางไว้ ผลลัพธ์ที่ได้ไม่จำเป็นต้องตรงตามที่ต้องการทุกครั้ง จึงต้องเปิดเว็บลองเล่น ปรับคำสั่ง แก้ไข และทดสอบใหม่

ตัวอย่างวิธีทำงาน:
1. วางสิ่งที่ผู้เล่นต้องทำและผลลัพธ์ที่คาดหวัง
2. ใช้ **Google Stitch** ช่วยออกแบบหน้าจอ
3. ใช้ **Codex Desktop** ช่วยพัฒนาและแก้ไขโค้ด
4. ทดลองเล่นด้วยตัวเอง จดปัญหา แล้วค่อยปรับทีละจุด
5. ตรวจว่าการแก้ไขไม่ได้ทำให้ระบบอื่นมีปัญหา

## เครื่องมือที่ใช้และเครื่องมือที่เคยลอง

| เครื่องมือ | ประสบการณ์ |
|---|---|
| Google Stitch | ใช้ช่วยออกแบบ UI |
| Codex Desktop | ใช้ช่วยเขียนและปรับโค้ด |
| ChatGPT, Gemini, Claude, Grok | เคยใช้และทดลองเพื่อศึกษาแนวทางต่าง ๆ ระหว่างพัฒนา |
| Meta Muse, Cursor, Google AI Studio | เคยทดลองใช้เพื่อศึกษาความสามารถและข้อจำกัด |
| ElevenLabs, Whisper | เครื่องมือด้านเสียงที่เคยศึกษา/ทดลอง; ไม่ได้อ้างว่ามีระบบเสียงดังกล่าวอยู่ในเกมแล้ว |
| ImageGen | README เดิมระบุว่าใช้ช่วยทำภาพตัวละคร |

**หมายเหตุ:** การทดลองใช้เครื่องมือไม่ได้หมายความว่าใช้ทุกตัวสร้างฟีเจอร์จริงใน Kotoba Quest และยังไม่ได้สรุปผลเชิงเปรียบเทียบที่มีตัวเลขทดสอบ

## สิ่งที่ผมได้เรียนรู้

ผมได้เห็นว่า AI บางตัวเหมาะกับการช่วยคิดหรืออธิบาย บางตัวเหมาะกับการเขียนและแก้โค้ด แต่ไม่มีตัวไหนที่ควรเชื่อผลลัพธ์โดยไม่ตรวจสอบ สิ่งที่สำคัญคือเราต้องรู้ว่าต้องการอะไร สั่งงานให้ชัด ลองใช้งานจริง และเข้าใจข้อผิดพลาดที่พบให้มากขึ้น

การทำ Kotoba Quest ทำให้ผมเริ่มศึกษา HTML, CSS, JavaScript, TypeScript และแนวคิดเกี่ยวกับการทำงานของเว็บ การจัดการสถานะ และฐานข้อมูล แม้ยังมีเรื่องที่ต้องเรียนรู้อีกมาก แต่จากที่เคยไม่รู้ว่าจะเริ่มอย่างไร ตอนนี้ผมเริ่มแยกส่วนของระบบและคิดวิธีตรวจปัญหาได้ดีขึ้น
